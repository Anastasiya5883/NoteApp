# Проверка ТЗ на противоречия

## Цель

Добавить в локальный эвристический анализатор ТЗ проверку наиболее очевидных логических и числовых противоречий. Проверка должна отдавать приоритет точности: неоднозначные формулировки пропускаются, чтобы снизить количество ложных срабатываний.

## Границы решения

- Анализ выполняется локально без AI-моделей, серверных API и новых внешних зависимостей.
- Проверяются отдельные предложения исходного текста.
- Сравниваются только утверждения, для которых удалось выделить одинаковый нормализованный предмет требования.
- Результаты носят рекомендательный характер и содержат исходные цитаты для проверки человеком.
- Расширенный семантический анализ, неявные смысловые конфликты и сравнение требований с внешней документацией не входят в объём этой задачи.

## Модель данных

В `AnalysisResult` добавляется обязательное поле `contradictions: Contradiction[]`.

`Contradiction` содержит:

- стабильный идентификатор;
- категорию `logical` или `numeric`;
- уровень важности;
- короткий заголовок;
- объяснение причины конфликта;
- две дословные цитаты из исходного ТЗ.

При чтении старых записей истории отсутствие поля трактуется как пустой массив, чтобы ранее сохранённые результаты продолжали открываться.

## Правила обнаружения

Анализатор разбивает текст на предложения и строит из каждого подходящего предложения нормализованное утверждение: предмет требования, действие или свойство, полярность и, если присутствует, числовое значение с единицей измерения.

### Логические противоречия

Противоречие фиксируется только тогда, когда два предложения относятся к одному предмету и содержат явно несовместимые утверждения. В первую версию входят строгие пары:

- обязательное / необязательное;
- разрешить / запретить;
- показывать / не показывать;
- создавать / не создавать.

Формулировки без распознанного предмета или с неявным отрицанием пропускаются.

### Числовые противоречия

Противоречие фиксируется, когда два предложения относятся к одному предмету и параметру, содержат одну и ту же нормализованную единицу измерения, но задают разные числовые значения. Например, требования «хранить журнал 30 дней» и «хранить журнал 60 дней» конфликтуют.

Разные числа не считаются конфликтом, если отличаются предмет, параметр или единица измерения. Одинаковые значения также не создают предупреждение.

### Устранение дублей

Одна и та же пара цитат и категория выдаются только один раз. Порядок результатов следует порядку первого появления конфликтующих требований в тексте.

## Поток данных

1. `analyzeText` выполняет существующий разбор объектов, реквизитов, разделов и пробелов.
2. Новый изолированный модуль проверки получает исходный нормализованный текст и возвращает `Contradiction[]`.
3. Массив включается в `AnalysisResult`, сохраняется в истории и передаётся существующему экрану результатов.
4. Экран и Markdown-экспорт отображают одинаковый набор противоречий.

## Интерфейс

На экране результатов добавляются:

- карточка статистики «Противоречий»;
- отдельный раздел «Противоречия в требованиях» перед разделом пробелов;
- карточка для каждого конфликта с категорией, объяснением и двумя исходными цитатами.

Если массив пуст, раздел показывает: «Явных противоречий не выявлено».

Шаг анализа получает подпись «Проверка противоречий», чтобы пользователь видел новую стадию обработки.

## Экспорт

Markdown-отчёт получает раздел «Противоречия в требованиях». Для каждого результата выводятся категория, объяснение и обе цитаты. При отсутствии результатов выводится тот же смысловой статус, что и в интерфейсе.

## Совместимость и обработка ошибок

- Пустой результат проверки является штатным состоянием.
- Нераспознанные или неоднозначные предложения игнорируются и не прерывают основной анализ.
- Старые результаты истории без `contradictions` нормализуются к пустому массиву на границе чтения данных.
- Существующие поля `AnalysisResult` и их поведение не меняются.

## Тестирование

Тесты анализатора должны подтвердить:

- обнаружение очевидной логической противоположности для одного предмета;
- обнаружение разных числовых значений одного параметра и единицы;
- отсутствие срабатывания для одинаковых утверждений;
- отсутствие срабатывания для разных предметов;
- отсутствие срабатывания для разных единиц или параметров;
- устранение дублей и стабильный порядок результатов.

Отдельные тесты должны подтвердить наличие противоречий в Markdown-экспорте и совместимое открытие старого результата истории без нового поля. После реализации выполняются полный набор тестов и production-сборка.
